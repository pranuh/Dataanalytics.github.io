1. Introduction: What is Data?

Data is simply recorded facts from daily life. Every modern action generates data—whether banking, shopping online, visiting a hospital, or posting on social media.

  • Structured Data: Organized neatly into rows and columns (e.g., bank accounts, customer rosters).
  • Unstructured Data: Free-form information without a fixed grid structure (e.g., audio, images, videos).
Icebreaker Question

"If Amazon has 500 million customers, where do you think all their customer and order information is stored?"

10–30 min

2. Before Databases: The File Era

Information storage evolved through clear milestones:

Paper Files → File System → Excel → Databases → Cloud Databases → Lakehouses

Consider a raw customer file like customers.csv:

customers.csv

IDNameCity
101RaviHyderabad
102AnuChennai
103RahulBangalore

As organizations scale, basic file systems introduce six core problems:

  • 1. Duplication: Customer details get re-typed across 10 different departmental files.
  • 2. Inconsistency: File A lists Ravi in Hyderabad, while File B lists Secunderabad.
  • 3. Search Difficulty: Answering "Find customers spending > ₹50,000" requires reading millions of rows manually.
  • 4. Concurrent Users: When 100 employees attempt to write to one file simultaneously, data gets overwritten.
  • 5. Security: Restricted fields (passwords, credit cards) cannot be masked per user.
  • 6. Reliability: A single computer crash during a save operation corrupts the entire file.

A database is an organized digital system designed to store, manage, retrieve, and safeguard large volumes of data efficiently.

4. What is a DBMS?

A DBMS (Database Management System) is the software layer controlling access to the underlying database.

Popular industrial DBMS platforms include: PostgreSQL, MySQL, Microsoft SQL Server, Oracle, and SQLite.

5. Relational Databases & Keys

In a Relational Database, data is organized into tables linked through shared key columns.

CUSTOMERS TABLE

customer_id (PK)namecity
101RaviHyderabad
102AnuChennai

ORDERS TABLE

order_id (PK)customer_id (FK)amount
5001101₹5,000
5002101₹2,000
5003102₹8,000
  • Row (Record): A single horizontal record entry (e.g., Customer #101).
  • Column (Field): A vertical attribute present for all rows (e.g., City).
  • Primary Key (PK): A unique identifier assigned to every row in a table (e.g., customer_id in Customers).
  • Foreign Key (FK): A column referencing the Primary Key of another table to connect them (e.g., customer_id in Orders).
80–95 min

6. Why SQL? First Queries

SQL (Structured Query Language) allows you to ask questions directly in declarative commands.

-- Goal: "Find all customers living in Hyderabad"
SELECT *
FROM customers
WHERE city = 'Hyderabad';
  • SELECT: What columns do I want to see? (* gets all columns).
  • FROM: Which table holds the target records?
  • WHERE: What filtering condition must be met?
