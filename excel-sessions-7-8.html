PivotTables

A PivotTable summarizes hundreds or thousands of rows into a compact table you build by dragging fields around — no formulas required. It answers questions like "total revenue by region" or "average order size by product" in seconds.

  1. Click any cell inside your data, then Insert tab → PivotTable.
  2. Confirm the data range and choose to place it on a New Worksheet.
  3. In the Field List, drag a category field (e.g. Region) into Rows.
  4. Drag a numeric field (e.g. Revenue) into Values — Excel defaults to Sum, but you can change it to Average, Count, Max, etc. by clicking the field and choosing "Value Field Settings."
  5. Drag a second category field (e.g. Product) into Columns to cross-tabulate two dimensions at once.
Mental model: Rows and Columns decide how the data is grouped; Values decides what's being calculated within each group. This maps directly to what SUMIF/SUMIFS did manually in Session 4 — a PivotTable is doing the same aggregation, just without you writing a formula per group.
Refreshing data: if the source data changes, the PivotTable does not update automatically. Right-click anywhere inside it and choose Refresh, or press Alt+F5.
E2

PivotCharts

A PivotChart is a chart built directly on top of a PivotTable — when you filter or drill into the table, the chart updates automatically along with it.

  1. Click inside an existing PivotTable, then PivotTable Analyze tab → PivotChart.
  2. Choose a chart type — bar and column charts work well for comparing categories; line charts for trends over time.
  3. The chart's field buttons let you filter directly from the chart itself, without going back to the table.
Why not just a regular chart? A regular chart is built on a fixed range and needs manual updating if categories change. A PivotChart inherits the PivotTable's grouping and filtering, so it stays correct as the underlying data grows.
E3

Slicers

A Slicer is a clickable button panel that filters a PivotTable (or PivotChart) visually — instead of using the dropdown filter arrows, viewers click a button for the category they want to see.

  1. Click inside a PivotTable, then PivotTable Analyze tab → Insert Slicer.
  2. Choose the field(s) to filter by — e.g. Region and Product.
  3. Click any button on the Slicer to filter the connected table/chart instantly; hold Ctrl to select multiple buttons at once.
  4. To connect one Slicer to more than one PivotTable (so both update together), right-click the Slicer → Report Connections → check every table it should control.
Why Slicers matter for dashboards: they're the interactive control that makes Session 8's dashboard possible — a non-technical viewer can explore the data by clicking, without ever touching a formula or filter dropdown.
E4

Basic charts for reporting

Choosing the right chart type matters more than making it look fancy — the goal is that a viewer understands the point in under five seconds.

Chart typeBest for
Column / BarComparing values across categories (Revenue by Region)
LineShowing a trend over time (Monthly Sales)
PieShowing parts of a whole — use only with 5 or fewer categories
Stacked ColumnComparing totals while also showing what each total is made of
  1. Select your data (including headers), then Insert tab → choose a chart type.
  2. Use Chart Design tab → Add Chart Element to add axis titles, data labels, or a legend.
  3. Right-click any chart → Select Data to change what it plots without rebuilding it.
Common mistake: defaulting to a pie chart for everything. Pie charts become unreadable past 5–6 slices — a bar chart almost always communicates the same comparison more clearly.

Practice activity: sales summary report

Using your Sales data from Session 3–4

  1. Build a PivotTable showing total Revenue by Region (Rows) and Product (Columns).
  2. Add a second PivotTable on the same sheet showing average Unit Price by Product.
  3. Insert a PivotChart (column chart) from the first PivotTable showing Revenue by Region.
  4. Insert a Slicer for Region and connect it to both PivotTables using Report Connections, so filtering one filters both.
  5. Click through the Slicer buttons and confirm both the table and the chart update together.
  6. Add a title to the sheet: "Sales Summary Report" and format it clearly — this is the direct precursor to Session 8's dashboard.

What makes a dashboard a dashboard

A dashboard is a single screen that answers the most important questions about a dataset at a glance, and lets a viewer explore further by clicking — not scrolling through raw rows. Everything you've learned so far is a building block:

Skill from earlier sessionsRole in the dashboard
Formulas & functions (Sessions 3–4)Power the KPI numbers
Data cleaning (Session 5)Makes sure the source data behind the dashboard is trustworthy
Lookups (Session 6)Pull details across tables into one clean source range
PivotTables, charts, Slicers (Session 7)Become the dashboard's visuals and interactive controls
Rule of thumb: if a viewer has to scroll to see the answer to their question, it's not a dashboard yet — it's a report. Everything important should fit on one screen.
F2

KPIs — picking the numbers that matter

A KPI (Key Performance Indicator) is a single number that summarizes performance — Total Revenue, Average Order Value, Number of Orders. Good dashboards show 3–5 KPIs prominently at the top, before any chart.

Total Revenue
=SUM of the Revenue column — the headline number
Total Orders
=COUNTA of the Order ID column — scale of activity
Avg. Order Value
=AVERAGE of Revenue — is revenue from many small orders or few large ones?
Top Region
Region with MAX Revenue via SUMIF/PivotTable — where to focus attention
Picking good KPIs: each one should answer a question a manager would actually ask. If you can't say out loud why a number is on the dashboard, it probably shouldn't be there.
F3

Layout and interactivity

A dashboard's layout should guide the eye the same way every time: KPIs first, then the most important chart, then supporting detail and filters.

  1. Build a dedicated Dashboard sheet — never put charts and Slicers directly on top of raw data.
  2. Place KPI cells across the top row, formatted large and bold, each with a short label above or below it.
  3. Arrange 2–3 charts below the KPIs — PivotCharts if they need to respond to filtering.
  4. Place Slicers along one edge (top or side) so they're easy to find, and connect them to every relevant PivotTable via Report Connections.
  5. Turn off gridlines on the Dashboard sheet (View tab → uncheck Gridlines) so it reads like a report, not a spreadsheet.
  6. Hide the raw data and helper PivotTable sheets from casual view (right-click the tab → Hide) so the Dashboard tab is what viewers see first.
Keep KPI cells as formulas, not typed numbers: if they're linked to the data (via SUM, AVERAGE, or a PivotTable's GETPIVOTDATA), the whole dashboard updates when the source data changes — which is the entire point of building one.

Mini Project 1: build the dashboard

Deliverable: one Dashboard sheet, built from your Session 3–7 workbook

  1. Consolidate your Sales, Products, and Orders data into a single clean source range (apply Session 5–6 skills if anything is inconsistent).
  2. Create a new sheet named Dashboard and turn off its gridlines.
  3. Add 4 KPI cells across the top: Total Revenue, Total Orders, Average Order Value, and Top-Performing Region — each driven by a formula or PivotTable, not typed in.
  4. Add a PivotChart showing Revenue by Region (column chart) and a second PivotChart showing Revenue by Product (bar chart).
  5. Insert a Region Slicer and a Product Slicer; connect both to every PivotTable feeding the dashboard.
  6. Format consistently: one accent color, one font, aligned KPI cards, and a clear title at the top of the sheet.
  7. Test it: click through every Slicer button and confirm all KPIs and charts update together, with no broken references.
  8. Hide the raw data and PivotTable working sheets so only the Dashboard and (optionally) a clean data sheet are visible.
Evaluation focus for Mini Project 1: does every number on the dashboard update correctly when a Slicer is clicked? A dashboard with beautiful formatting but static numbers has missed the point of the entire course.
